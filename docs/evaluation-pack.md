# 脱敏评估包清单

**这是什么**：给认真评估的人一份能上手看的样本——一段输入、一份输出、一份怎么读的说明。
**这不是什么**：不是代码包，不是数据集，不是可以拿去复现方法的材料。

评估包通过 GitHub Releases 附件或按需邮件发送，不进主仓库。主仓库始终只有说明与截图。

---

## 一、包里放什么（五项，缺一项就不发）

| # | 内容 | 形态 | 脱敏要求 |
|---|---|---|---|
| 1 | **输入样本** | 1 段 60–120 秒视频 | 见下方"素材合法性"一节，四条必须同时满足 |
| 2 | **输出报告** | PDF + HTML 各一份 | 双层水印；人名改为编号或匿名化；无元数据残留 |
| 3 | **读数说明** | 1–2 页 PDF | 只解释怎么读表，不解释怎么算 |
| 4 | **对照表** | 1 页 CSV 或图片 | 报告中每个视图 ↔ 对应的时间点，供人工抽查 |
| 5 | **保密声明** | 文本 | 明确"仅评估用途、不得转发、不得用于训练" |

## 二、素材合法性（第 1 项的四条硬门槛）

评估包的输入片段必须**同时**满足：

- [ ] 画面来源是我们自己录制，或已取得书面授权的素材；
- [ ] 不使用电视台转播画面、流媒体屏摄、赛事官方素材——除非客户本人提供并书面确认有权使用；
- [ ] 画面中出现的赞助商标识、转播字幕、场边 LED，**保留不动**（不做二次处理，避免制造新的版权问题）；
- [ ] 片段内不出现可辨识的未成年人面部特写。

> 这一条最容易被忽略。版权不在我们手上时，宁可换一段自有素材，也不要为了画面好看去用转播片段——
> 评估包一旦外流，责任在我们。

## 三、脱敏的具体动作（逐项打勾）

**身份层**
- [ ] 球员真实姓名、球衣背面姓名 → 编号（P01、P02…）或位置代号；
- [ ] 队徽、俱乐部标识 → 纯色块或通用图形；
- [ ] 教练组、裁判、工作人员 → 从画面或报告中移除；
- [ ] 场地名称、看台标语、可定位的广告牌 → 裁剪或模糊。

**方法层**（这一层比身份层更重要）
- [ ] 报告中不出现任何模型名、库名、算法名、参数名；
- [ ] 不附运行日志；如必须给，先删掉所有与内部路径、模型加载、耗时分解相关的行；
- [ ] 不暴露内部目录结构（报告的文件树应为扁平的、面向客户的命名）；
- [ ] PDF/HTML 导出前清除元数据（作者、机器名、创建软件版本、内嵌路径）；
- [ ] 图片不保留 EXIF。

**商务层**
- [ ] 全页水印：`EVALUATION SAMPLE · NOT FOR REDISTRIBUTION`（斜向、半透明、覆满）；
- [ ] 页脚标注版本号与生成日期；
- [ ] 不含报价、不含客户名单、不含任何第三方名称；
- [ ] 联系方式只留 `jov611@gmail.com` 与站点链接。

## 四、体积与分发

- 单文件上限 **25 MB**（GitHub Releases 单个附件限制）；超了就把视频裁短，不要压到看不清。
- 评估包**不进 git 历史**。用 Release 附件，或单独发邮件。理由：git 历史删不掉，附件可以下架。
- 分发前登记：谁、什么时候、拿到了哪一版。这份登记表存在本地，不进仓库。

## 五、给谁、什么条件下给

| 对象 | 给什么 | 前置条件 |
|---|---|---|
| 公开访客 | 只看仓库里的截图与说明 | 无 |
| 填了评估表的潜在客户 | 输出报告 + 读数说明（**不含输入视频**） | 邮箱确认，一句业务背景 |
| 签署 NDA 的买方 | 完整五项 | NDA 生效 |
| 尽调阶段 | 完整五项 + 私有仓库限时只读 | NDA + 明确评估范围 |

**顺序不能反。** 输入视频是五项里唯一可能带来版权风险的东西，它排在最后给。

## 六、产出这份包之前必须解决的

- [ ] 手上有至少一段**自有或已授权**的完整比赛录像（当前状态：待确认）；
- [ ] 报告导出已能稳定清除元数据（当前状态：待验证）；
- [ ] 匿名化是可重复的流程，而不是手工改一份（当前状态：待建立）。

三项没打勾之前，评估包只发第 2、3、4、5 项，第 1 项留空并注明"输入样本在 NDA 后提供"。
**这样反而更专业：愿意说"这一段现在不能给"的人，比什么都给的人可信。**
