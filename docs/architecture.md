# 系统边界说明

本文件只描述**模块边界、输入输出契约与工程约束**，不描述算法、参数或模型结构。
这是刻意的：仓库对公众开放，方法细节不属于公众信息。

## 流水线阶段（只看边界，不看实现）

```
① 接入         单一视频源 → 解码 → 帧序列
② 画面理解     帧序列 → 球场范围、人员位置、球位置（帧内表达）
③ 坐标统一     帧内表达 → 米制球场坐标（105 × 68）→ 跨场次可比较的运动序列
④ 战术建模     运动序列 + 事件 → 战术条目、对抗片段、阶段划分
⑤ 产出         战术条目 → 9 视图 / 12 叠加 / 3D 沙盘 / 事件轴 / 双语文档
```

每一阶段对外只暴露三样东西：它接受什么数据形状、产出什么数据形状、失败时的降级行为。
阶段内部怎么做，不在本文件的范围内。

## 输入输出契约

| 阶段 | 输入 | 输出 | 失败时的行为 |
|---|---|---|---|
| ① 接入 | 广播画面 / 屏摄 / 本地录像 | 帧序列 + 时间戳 | 画面不可解码则整场拒收，不做部分处理 |
| ② 画面理解 | 帧序列 | 帧级人员与球的位置 | 单帧丢失不阻断，按前后帧连续性补齐；连续丢失超阈值则该段标注为低置信 |
| ③ 坐标统一 | 帧级位置 | 米制坐标下的轨迹 | 无法可靠确定球场范围时，该场降级为"仅画面视图"，并在报告中显式标注 |
| ④ 战术建模 | 轨迹 + 事件 | 战术条目、片段、阶段 | 数据不足以判定的条目**不输出**，而不是给一个猜测值 |
| ⑤ 产出 | 战术条目 | 视图、沙盘、时间轴、双语报告 | 任一视图渲染失败不影响其余产出 |

## 三条工程约束（可用来判断我们是否在说真话）

1. **不猜。** 数据不足以支撑的结论，宁可不写。报告里出现的每一个百分比，要么是实测，
   要么明确标注为模型推算。
2. **可追溯。** 报告中每条结论都能跳回它依据的那一帧。没有回跳能力的结论，我们不写进
   正式报告。
3. **不出机。** 默认本地运行，原始视频不上传。任何需要云端的交付形态，都在合同里单独
   写明数据流向，并需客户书面同意。

## 与外部系统的接口面

- **文件级**：报告以 PDF / HTML 交付，自包含，无需安装。
- **数据级**：结构化结果可按约定的字段表导出，供客户的平台消费。
- **集成级**：作为模块嵌入客户产品线的形态（白标 / API），按项目单独定义边界，不在本仓库
  范围内展开。

## 明确不在本文件范围

模型结构、训练方式、球场配准的具体解法、追踪与球队归属的实现、战术判定规则、精度阈值、
性能参数。这些内容只在 NDA 之下、在私有仓库中讨论。
